# МедПраво: публикации для медицинского центра в Калуге

Лента новых нормативных документов из открытых источников: федеральные требования, Калуга и Калужская область, ОМС, МРТ/КТ, дети, анестезия, дневной стационар и общие требования к работе центра. Без ИИ и отправки почты.

## Как пользоваться

Сайт: https://levshamv.github.io/medpravo/

Публикации можно искать по словам и номеру, фильтровать по теме и источнику. Заголовок уточняется только по описанию официального источника. Исходное название можно раскрыть под заголовком. Метка «просмотрено» хранится в этом браузере; между компьютерами она не синхронизируется. Очистка данных браузера удаляет отметки.

Лента и код публичные. Медицинских сведений о пациентах, паролей и ключей в репозитории нет. Не загружайте сюда личные документы или данные пациентов.

Обновление: GitHub Actions запускает сборщик примерно каждые 6 часов, в 03:17, 09:17, 15:17 и 21:17 по Москве. Плановый запуск может задержаться или быть пропущен GitHub. Если в публичном репозитории 60 дней нет активности, расписание отключается. Проверяйте дату последнего сбора на сайте и вкладку Actions. Сборщик сохраняет данные в ветку medpravo-state после каждой проверки; состояние не зависит от временного кэша Actions.

Ручной сбор: кнопка «Запустить на GitHub» → Run workflow → Run workflow. Нужен вход в аккаунт с доступом к репозиторию. После окончания обновите сайт.

## Источники и ограничения

Реестр содержит 26 источников, 22 включены по умолчанию. Конфигурация sources.json: enabled true/false определяет участие источника в сборе. Во вкладке «Источники» показан реальный результат последней проверки. При ошибке доступа отсутствие новых документов не подтверждено. Частичный сбор означает, что продолжается очередь страниц/документов; полный охват всех публикаций не гарантирован.

Госдума, дополнительный портал текстов pravo.gov.ru, ГРЛС и API проектов выключены: нужны отдельная настройка или устойчивый доступ. Главный портал официального опубликования включён отдельно. Источники выбираются по открыто доступным разделам и не включают закрытые базы КонсультантПлюс/Гарант.

Ссылки одного документа не создают повторные публикации. Новые акты о внесении изменений собираются; замена содержания старого файла по прежней ссылке не отслеживается. Темы определяются по ключевым словам и не являются юридическим заключением. Дата обнаружения отличается от даты принятия/публикации; первый импорт отмечен как первоначальная подборка.

Для файлов ТФОМС предусмотрены публичные копии под контрольной суммой. Ограничение одного файла 20 МБ, всех текущих копий 60 МБ. Копирование новых файлов ограничено по времени; не для каждого документа обязательно будет копия. Если её нет, остаются ссылка на файл и страница официального источника. Сверяйте существенные документы в первоисточнике; копия — версия на момент получения. Старые файлы по тому же URL не сравниваются. Остальные документы открываются на сайтах источников, при проблемах с российскими сертификатами используйте Яндекс Браузер.

Доступ из GitHub нужно оценивать по результатам самого GitHub Actions: удачная проверка с другого компьютера его не подтверждает.

## Результат первого запуска на GitHub

Проверка 15 октября 2026 по московскому времени: 642 публикации в сохранённой истории, включая 446 ранее найденных и 196 добавленных этим запуском. Ответили 13 из 22 включённых источников (полный охват всех их разделов не подтверждён). Сохранены 13 копий файлов ТФОМС, скачивание DS5kTS.zip из ленты проверено.

Не прочитались каталоги ФФОМС, ТФОМС Калужской области, Минздрава и правительства Калужской области, Роспотребнадзора и его управления по Калужской области, Роструда, Роскомнадзора и ФАС. Дополнительная проверка тех же адресов на обычных Linux и Windows runners, с приоритетом IPv4 и по HTTP/HTTPS, не восстановила доступ. Отдельные известные файлы ТФОМС доступны, но это не подтверждает сбор новых ссылок из закрытого каталога. На сайте показано предупреждение.

Это рабочая бесплатная лента с ограничениями доступа. Для устойчивого прямого доступа к недоступным сайтам может понадобиться сеть в России; полнота доступа через такую сеть здесь не проверена.

## Развёртывание

Settings → Pages → Source: **GitHub Actions**. После загрузки файлов сбор стартует автоматически; последующие запуски работают без включённого компьютера и без Docker. Свой домен не требуется. Стандартные Actions в публичном репозитории бесплатны; используются обычные runners, артефакт сайта хранится 1 день. Изменения тарифов/квот проверяйте в документации GitHub.

Если Pages ещё не включён, сбор и сохранение истории всё равно выполняются; после включения повторите запуск workflow. В разделе Actions открывайте последнюю проверку: в Summary видны статусы источников. Зелёный workflow подтверждает работу программы, но не означает доступность каждого сайта.

## Проверка разработчиком

Python 3.12+, стандартная библиотека; Node нужен для теста браузерного клиента.

```
python -m unittest discover -s tests -p 'test_*.py'
node tests/test_github_client.js
python github_collect.py --export-only
```

github_collect.py запускает однократный сбор и создаёт site/data.json и статический сайт. История SQLite упаковывается в .state/persist/state.sqlite.gz; HTTP-кэш и персональные отметки в неё не попадают. В очереди сохраняются страницы, документы и сроки повторных попыток. Повреждённая история останавливает запуск, а не сбрасывается незаметно. github_state.py использует отдельную ветку для состояния, проверяет допустимые имена файлов и не публикует рабочую папку целиком.

Все actions закреплены по SHA официальных версий. Workflow запускается только из main и по расписанию/ручной кнопке, без pull_request_target. Браузер не получает GitHub-токен. Разрешения записи ограничены этим репозиторием; штатный временный GITHUB_TOKEN выдаёт GitHub Actions.
