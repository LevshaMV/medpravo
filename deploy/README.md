# Российское соединение для МедПраво

Сайт и сборщик остаются на GitHub. Российский сервер служит только выходом для HTTPS-запросов к официальным источникам. Docker, OpenAI, свой домен и почта не нужны. Содержимое HTTPS не расшифровывается релеем; сертификаты проверяет сборщик.

Постоянный российский сервер подключён. GitHub Actions создаёт временный SSH-туннель во время полного сбора. В конфигурации включены все 26 источников; фактический результат, ошибки и оставшаяся очередь показаны в разделе «Источники». Включённый источник не означает подтверждённый полный охват.

Для установленного релея используется Ubuntu 24.04, Россия (Москва), 1 CPU, 1 ГБ памяти, 10 ГБ диска, один публичный IPv4. Текущая стоимость и баланс указаны в кабинете провайдера. Повторно покупать сервер для переноса репозитория не нужно.

Официальный тариф: https://vdsina.ru/pricing/standard

## Подключение после создания сервера

1. Создать отдельный SSH-ключ только для МедПраво. Его закрытая часть не публикуется в коде, архиве или чате.
2. Передать на сервер russian_proxy.py, network.py, sources.json и deploy/install_relay.sh из этого пакета.
3. На выделенном сервере выполнить установщик с открытой частью ключа. Он установит Python и сервис, который слушает только 127.0.0.1:8118. Пользователь medpravo-relay разрешает только SSH-перенаправление к этому порту и не даёт выполнять команды оболочки.
4. Через консоль провайдера получить публичный ключ SSH самого сервера. Не принимать неизвестный ключ вслепую.
5. В своём репозитории → Settings → Secrets and variables → Actions добавить:
   - переменную MEDPRAVO_RELAY_HOST: публичный адрес сервера;
   - секрет MEDPRAVO_RELAY_KEY: отдельный закрытый ключ МедПраво;
   - секрет MEDPRAVO_RELAY_KNOWN_HOSTS: адрес сервера, пробел, проверенный публичный ключ SSH сервера.
6. Запустить обычный collect.yml без галочки «Только переопубликовать». Проверить Summary, даты и происхождение сетевой проверки по каждому источнику на сайте.

Когда эти настройки отсутствуют, программа продолжает обычный сбор из GitHub с прежними сетевыми ограничениями. При ошибке настроенного SSH-соединения запуск останавливается и сохраняет ранее опубликованную ленту. Перепубликация сохранённых данных не требует релея. Никакие GitHub-задачи на личном компьютере не устанавливаются.

Ключ на сервере ограничен одним локальным портом. Сам релей допускает только HTTPS на 443 к доменам из sources.json; частные IP и произвольные адреса запрещены. SSH-туннель создаётся только на время проверки; его временные ключи удаляются в конце задания.

## Проверка работы и перенос

При переносе существующего репозитория GitHub сохраняет секреты вместе с ним. После принятия переноса новым владельцем проверьте Settings → Pages → Source: GitHub Actions и выполните полный collect.yml. Убедитесь, что шаг подключения релея прошёл, адрес сайта относится к новому аккаунту, время последнего сбора обновилось, а история осталась на месте. При копировании проекта в отдельный новый репозиторий защищённые настройки нужно внести заново. Прочитанные каталоги не означают полный охват всех документов: очереди обхода сохраняются.
